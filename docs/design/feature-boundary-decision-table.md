# 墨览功能边界裁定表

版本：v1  
日期：2026-07-04  
对应任务：D0.2  
依据：`PRD.md`、`TODO.md §0.7`、`docs/full-plan.md`

## 1. 边界原则

墨览只做“散落文件进入 AI 工作流”的必要能力，不做泛办公、泛知识库、泛云盘。

| 原则 | 裁定 |
|---|---|
| 阅读先于识别 | 文件打开后直接阅读，AI 识别、云备份、导入提示只能后台或用户主动触发 |
| 手机轻、电脑重 | 手机只做 Markdown / JSON 轻核心和当前文件轻转换；Office / PDF / PPT / Excel 重转换交给电脑 CLI / GUI |
| 复制优先 | 提示词、代码块、JSON 字段复制优先级高于高级编辑和复杂转换 |
| 离线优先 | V1 不依赖账号和后端；云端只能从 V2 开始，且默认不上传 |
| 国内优先 | 微信、QQ、系统分享是 V1；海外社交平台不做专项适配 |
| 不写兼容包袱 | 没有明确历史要求时，按当前 PRD 和 TODO 裁定实现 |

## 3. PRD 冲突最终裁定

| 冲突 | 最终裁定 | 原因 |
|---|---|---|
| 批量转换中心既在“当前最高优先级”又在 V1.5 | 归 S6 / V1.5；V1 只做当前文件转换后直接分享 | V1 要优先闭合手机收到文件后的单文件链路 |
| PRD 说电脑端不进 V1，但又要求电脑脚本 | CLI 属 V1；桌面 GUI 不进手机 V1 主线 | CLI 是 AI 可读工作流基础，不抢手机端主流程 |
| JSON -> PDF / Word 在 P0 和 V1.5 间冲突 | V1 只做 JSON -> Markdown；JSON -> PDF / Word 到 V1.5 | 需要规则化文档设计，避免生成不可读输出 |
| 云端最终重要但 V1 离线优先 | 云端不阻塞 V1；S7 前必须先完成设计 | 隐私和信任优先，不能默认上传用户文件 |
| Android 悬浮快贴很有价值但权限敏感 | App 内快贴先做；系统悬浮窗到 V2 | 需要用户主动授权和隐私说明 |

## 4. 不做清单

| 不做 | 可替代能力 |
|---|---|
| 重型 Markdown 编辑器 | 原文编辑、预览、草稿、副本 |
| Obsidian 类知识库 | 最近文档、收藏、有用资源、AI 文件资料库 |
| Notion 类数据库和项目管理 | 文件状态、集合、标签 |
| 完整办公套件 | Markdown / JSON 转 PDF / Word 用于分享 |
| 专业 JSON IDE | JSON 树、搜索、复制字段、JSONPath、Markdown 字段预览 |
| 提示词社区 / 市场 | 本地提示词库、团队提示词库后置 |
| 默认云盘 | 用户主动保存的云备份和历史找回 |
| 内置通用 AI 聊天 | AI 阅读卡片、AI 可读转换、CLI / MCP 读取入口 |
| 默认监听剪贴板或读取其他 App 输入框 | 用户主动导入剪贴板、主动复制 |
| OCR / 扫描件处理 | Office / PDF 文本转换，OCR 后置评估 |
| 海外社交平台专项 | 系统分享面板覆盖 |

- V1、V1.5、V2、V3 的边界不互相抢范围。
- 明确列出不做内容和替代能力。
- 保留 `TODO.md §0.7` 三条冲突裁定。

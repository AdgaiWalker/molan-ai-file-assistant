## 1. 评分口径

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 频率 | 偶尔使用 | 每周多次 | 每天或每次打开都会用 |
| 价值 | 锦上添花 | 明显提升效率 | 没有它产品不成立 |
| 风险 | 失败影响小 | 影响部分核心流程 | 失败即入口或信任崩 |
| 成本 | 文档 / 小改动 | 跨组件或跨端 | 真机 / 原生 / 云端 / 发布 |

排序规则：

```text
优先分 = 频率 * 2 + 价值 * 3 + 风险 * 2 - 成本
```

价值权重最高，因为墨览要先证明“收到文件后比所有工具都快”。风险权重次之，因为入口、隐私和外部契约一旦错，会影响后续全部链路。

## 6. 执行裁定

1. 真机入口验证排第一，即使它是环境任务，也决定后续代码是否有意义。
2. 复制闭环优先于批量转换，因为复制是每次文件打开后的高频动作。
3. 当前文件转换优先于批量转换，批量转换归 V1.5。
4. CLI 转换和 JSON 输出属于 V1，因为它是电脑端 AI 可读主入口。
5. 云端所有实现必须晚于云端设计、隐私设计和数据模型设计。
6. P3 商业化只在个人工具闭环、发布、云端最小闭环后启动。

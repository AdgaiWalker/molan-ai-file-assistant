# 墨览发布、监控与回滚清单

版本：v1

日期：2026-07-21

依据：`PRD.md §15`、`TODO.md G-007`、`docs/design/key-metrics-design.md`

## 1. 使用方式

本清单服务于一次真实发布或一次测试版本演练。

- 每个平台一行一行执行，不跳步骤；
- `负责人` 暂时保留占位，开始真实发布前必须补人名；
- `证据` 一栏必须填写命令输出、后台截图、构建产物路径、SHA256 或录屏路径；
- 监控只记录状态、计数、错误码、队列长度、构建号、设备与时间，不记录文件正文、提示词正文、Token 或本地私密路径。
- 开始执行前，先跑一次 `node scripts/prepare_release_wave.mjs --out default`，把官网公开面自检、当前版本号、包 ID、已发现产物快照、对外交付首选产物 / SHA256 和 G-007 演练模板一起固定下来。
- 如果本地已经有候选包，优先从 `docs/validation-runs/2026-07-21/release_dry_run/release-readiness-snapshot.md` 的“当前对外交付首选产物”表，或对应 JSON 的 `deliveryManifest` 字段抄产物路径与 SHA256，再去补商店 / 官网 / 下载站记录。
- `node scripts/prepare_release_wave.mjs --out default` 现在还会顺手往 `docs/validation-runs/2026-07-21/release_dry_run/evidence/` 写一批文本种子：Android / iOS / 桌面 / CLI 的当前候选包与 SHA256、官网公开入口清单、回滚记录占位和 `release-candidate-manifest.json`。这些文件不能代替真实演练证据，但可以直接作为填写 G-007 演练单和正式记录的起点。

## 5. 回滚触发条件

满足任一条件即可发起回滚，不等待“再观察一会儿”：

- 新版本出现文件正文损坏、错误覆盖、结果串链或删除后仍可读；
- 同步成功率持续跌破阈值，且短时间无法通过热修或配置恢复；
- Android/iOS 出现大面积启动失败、白屏、崩溃或 ANR；
- CLI/MCP 输出契约漂移，导致现有 AI 调用链无法继续工作；
- 官网下载链接错误、签名错误或发布包 SHA256 不匹配；
- 审计链路缺失、误记正文或发生未授权正文读取。

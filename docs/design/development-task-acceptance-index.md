# D6.5 开发任务验收与失败状态索引

## 1. 通用关闭规则

每个 S 层开发任务关闭时必须满足：
1. TODO 状态更新为 `[x]`、`[v]`、`[~]` 或 `[!]`，不能只改代码不改 TODO。
2. 按 TODO §17 补证据。
3. 跑对应端验证。
4. 单项中文 commit。
5. 涉及公共契约时，必须说明是否保持兼容。

## 2. 证据类型

| 任务类型 | 必要证据 |
|---|---|
| 代码任务 | 文件路径、实现点、typecheck/test 结果 |
| 真机任务 | 设备、系统、来源 App、步骤、截图/录屏 |
| 转换任务 | 输入样例、输出文件、失败样例、错误信息 |
| 发布任务 | 产物文件名、大小、SHA256、下载链接 |
| 文档任务 | 文档路径、更新章节、PRD 一致性说明 |
| 性能任务 | 设备、包体大小、冷启动、转换耗时 |

## 3. 端侧验证

手机：

```bash
cd mobile
npm run typecheck
npm test
```

桌面：

```bash
cd desktop
npm run typecheck
```

CLI：

```bash
cd desktop/cli
npm run typecheck
npm run build
npm test
```

按任务影响范围选择验证；公共模型、状态机、CLI 契约变更必须跑相关测试。

## 4. 失败状态要求

| 领域 | 必须覆盖的失败状态 |
|---|---|
| 打开文件 | 无权限、文件不存在、类型不支持、content URI 读取失败 |
| Markdown 阅读 | 空文件、大文件、解析失败、滚动位置恢复失败 |
| JSON 阅读 | 非法 JSON、大 JSON、搜索无结果、复制失败 |
| 编辑 | JSON 校验失败、保存失败、草稿恢复、取消编辑 |
| 复制 | 剪贴板失败、空内容、敏感字段提示 |
| 转换 | 输入不存在、格式不支持、转换失败、输出失败、取消、重试 |
| 分享 | 分享面板不可用、目标 App 失败、文件不存在 |
| 云同步 | 离线、未登录、设备撤销、冲突、删除、上传失败 |
| 发布 | 构建失败、签名缺失、checksum 不一致、账号缺失 |

没有失败状态说明的 S 任务不能关闭为 `[x]`。

## 5. 测试裁定

必须写测试：
- 纯逻辑规则。
- 状态机。
- CLI/MCP/API 外部契约。
- 转换 fixture 回归。

不写测试：
- UI mock-heavy 组件。
- 标准库薄封装。
- 类型系统已证明的不变量。
- 真机/E2E 先按手动脚本验收。

## 7. 阻塞标记

使用 `[v]`：
- 需要真机、商店、账号、证书、真实下载链接。

使用 `[!]`：
- 敏感文件风险。
- 公共契约可能破坏。
- 发布产物 checksum 不一致。
- 云端隐私边界无法保证。

使用 `[~]`：
- 已有基础实现，但缺 fixture、真实环境、边界体验或证据。

## 8. 验收口径

- 每个 S 阶段都有验收重点和失败状态来源。
- 测试写/不写规则与 AGENTS/TODO §20 一致。
- 真机、账号、证书、发布链接类任务有阻塞标记规则。
- 后续开发关闭任务时能直接引用本文和对应 D 层文档。

# Clean Code Review: 最近交互重设计代码

日期：2026-07-28

## Summary

最高杠杆风险是桌面收件箱和 Android 首页把状态编排、平台调用、业务分支与大段 UI 同时塞进单个文件。代码当前可运行，但任何权限、同步或文件状态改动都会扩大回归面。对抗裁决是：保留已经验证的行为和视觉，拆开状态访问、纯展示规则与子组件；不引入新的通用框架、基类或兼容层。

## Findings

### P1: 桌面收件箱成为 578 行的多职责变更中心
- **原则**: 单一职责 / 结构清晰度 / 项目规范
- **位置**: `desktop/src/components/InboxPanel.tsx:19`
- **级别**: 高
- **问题**: 同一个组件同时持有登录表单、同步快照、IPC 调用、忙碌与错误状态、转换编排、权限、删除、冲突、关系详情和完整页面渲染。`window.api` 直接散落在 JSX 回调中，也违反仓库要求的数据访问下沉。
- **建议**: 提取 `useInboxController` 统一平台调用与错误状态；把文件卡片拆成独立展示组件；将筛选、状态、格式与时间规则移动到纯展示模块。
- **Why now**: 收件箱是跨端与 AI 主链中心，后续任何状态扩展都会继续放大这个文件。
- **红蓝裁决**: 蓝方“集中方便追踪整条链路”的辩护只在原型期成立；现在已有固定契约和回归测试，拆分更容易追踪且不改变行为。

### P2: Android 首页与文件卡片包含过深分支和过多职责
- **原则**: 单一职责 / 结构清晰度 / 函数参数
- **位置**: `native/androidApp/src/main/kotlin/com/molan/reader/ui/home/HomeScreen.kt:51`
- **级别**: 高
- **问题**: 490 行文件同时实现首页、同步、冲突、文件卡、菜单、删除确认和展示格式；`LibraryDocumentCard` 接收 9 个参数，并在菜单内嵌套多层状态判断。
- **建议**: 按真实 UI 边界拆出文件卡、同步卡和冲突区；保留 Compose 的显式状态提升方式，不为了减少参数额外制造单实现接口。
- **Why now**: 首页是手机第一主线入口，状态和动作继续增加时最容易出现阅读困难与误改。
- **红蓝裁决**: 蓝方正确指出 Compose 常见显式回调，但这不能为 490 行聚合文件辩护；拆文件，暂不造事件总线。

### P3: 桌面样式表按功能持续增长但没有模块边界
- **原则**: 结构清晰度 / 项目规范
- **位置**: `desktop/src/styles.css:1`
- **级别**: 中
- **问题**: 约 2,000 行样式同时覆盖基础令牌、布局、阅读器、转换、快贴和收件箱。搜索仍可定位，但变更审查和删除未使用样式的成本持续升高。
- **建议**: 后续按 `base / shell / reader / convert / prompt / inbox / accessibility` 拆分，并由单一入口按层次导入；只做机械移动，不改变选择器或优先级。
- **Why now**: 本轮视觉系统已稳定，正是固定层次后再继续加页面的窗口期。
- **红蓝裁决**: 暂不在第一批动 CSS；机械拆分收益明确，但优先级低于正在承载业务状态的组件。

### P4: Reader 的 JSON 操作复制同一套成功与失败状态处理
- **原则**: DRY / 魔法数字
- **位置**: `desktop/src/components/ReaderPanel.tsx:61`
- **级别**: 中
- **问题**: 校验、格式化和压缩三条路径分别维护 `JSON.parse`、清错、成功文案和失败文案；格式化缩进 `2` 也没有命名。
- **建议**: 提取统一失败处理和 JSON 变换函数，使用命名常量表达缩进；保留三个用户动作和现有输出不变。
- **Why now**: 下一次增加 JSON 工具时很容易出现第四套略有差异的异常路径。

### P5: 快贴复制反馈时长是无语义裸值
- **原则**: 魔法数字
- **位置**: `desktop/src/components/PromptPanel.tsx:69`
- **级别**: 低
- **问题**: `1200` 无法从调用点判断是复制反馈时长，也不方便统一调整。
- **建议**: 提取 `COPY_FEEDBACK_DURATION_MS`，不改变定时行为。
- **Why now**: 低风险、零行为变化，可在本轮顺手清理。

## Good Patterns To Keep

- 用户可见文案已经集中在字符串文件，避免新的 JSX/Compose 硬编码文案。
- 桌面端权限、危险操作和技术信息使用渐进披露，组件拆分时应保持现有层级。
- Android/iOS 继续使用各自平台组件，没有为了视觉一致性共享 UI。
- `DesktopInboxDocument`、`DesktopSyncSnapshot` 等类型明确，没有使用 `any` 或双重类型断言。
- 现有桌面转换、同步索引和错误契约测试提供了可靠重构底座。

## Test Gaps

- 为收件箱的筛选、待转换判断、格式方向、字节与时间展示增加纯逻辑测试；这些规则无 UI、易静默破坏。
- 不新增 mock-heavy React/Compose UI 测试；继续使用真实 Electron 和 Android 构建验证组件拆分。
- 重构后必须重跑 Desktop 32 项测试、TypeScript 类型检查、Electron build，以及 Android debug build 和 unit tests。

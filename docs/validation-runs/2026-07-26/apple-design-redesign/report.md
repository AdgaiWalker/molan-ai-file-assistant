# Apple Design 对抗式交互审理与重设计

日期：2026-07-26

## 裁决

**重做桌面工作台的信息架构和动作层级；保留 iOS、Android 的平台原生表达，只同步“阅读优先、同步次级、危险操作收起”的交互原则。**

这不是一次“苹果风格换皮”。本轮判断标准是四个用户目标：

1. **安全与可预测**：授权、上传、删除的范围必须明确，危险动作不能与主任务并列。
2. **理解**：用户进入页面后应立即知道自己在哪里、下一步是什么、文件当前处于哪一阶段。
3. **完成**：打开、转换、AI 读取和复制必须比配置、技术信息更容易到达。
4. **愉悦**：反馈即时、层级稳定、视觉安静；动效帮助理解而不是表演。

## 红方攻击、蓝方辩护与最终裁决

| 争议 | 红方攻击 | 蓝方最强辩护 | 最终裁决 |
|---|---|---|---|
| 桌面四个平级页签 | 产品定义是 AI 文件工作台，但旧界面更像四个独立 Demo；收件箱还排在第三 | 平级页签实现简单，切换成本低 | 推翻。改为常驻侧栏，AI 收件箱成为第一入口；阅读、转换、快贴保留为明确工具 |
| 收件箱文件卡 | 同一张卡暴露打开、可读副本、授权、转换、归档、关系和三种删除，用户无法判断主动作 | 全部平铺可以少一次点击 | 推翻。主层只保留“打开/转换/授权”，关系、技术信息、归档与删除逐层展开 |
| AI 集合权限 | “授权全部”和“撤回全部”与页面标题并列，容易误触，也造成权限焦虑 | 全局权限是高频管理能力 | 部分保留。能力不删除，但移入“AI 读取权限”说明区，操作前继续确认 |
| 状态表达 | 状态芯片、原始 ID、ISO 时间和计数同时出现，技术正确但不帮助决策 | 调试阶段需要完整信息 | 分层。主层改成“已到电脑 → 可供 AI 阅读 → 已授权 AI”三步状态；原始设备 ID、授权时间和对象关系移入技术信息 |
| 提示词快贴 | 设置、新建、编辑、组合、打开输出目录均无真实行为；“已同步”也是不真实承诺 | 这些按钮表达后续产品方向 | 删除。界面只保留已经可用的搜索、选择、复制、置顶和独立窗口；明确标注为内置模板 |
| 手机首页同步区 | 登录表单长期占据打开与文件库之间，违背“阅读不能被账号或同步阻挡” | 同步入口可发现性高 | 收敛。iOS 使用原生 DisclosureGroup，Android 使用可中断的 spring 展开区；默认只显示连接状态 |
| Android 删除动作 | 三种删除长期平铺在每张卡片上，既焦虑又易误触 | 删除范围需要透明 | 推翻。改为“更多”菜单，保留三种范围及原确认说明 |
| 全平台统一视觉 | 统一玻璃、阴影和动效最容易产生品牌一致性 | 跨端看起来更像同一产品 | 拒绝。统一任务语言与权限原则，不统一控件；iOS 保持 SwiftUI，Android 保持 Material，桌面使用 macOS 适配的工作台布局 |

## 新的信息架构

```text
桌面 AI 文件工作台
├── AI 收件箱（默认）
│   ├── 同步连接与摘要
│   ├── 搜索 / 状态筛选
│   └── 文件工作流
│       ├── 主动作：打开 / 转换 / 授权
│       ├── 更多：关系与技术信息
│       └── 危险区：归档与删除
├── 文件阅读
│   ├── 文件身份
│   ├── 预览 / 编辑
│   └── JSON 工具 / 复制 / 保存副本
├── 格式转换
│   ├── 拖拽或选择文件
│   ├── 输出位置
│   └── 任务与明确结果
└── 提示词快贴
    ├── 搜索与选择
    ├── 单击复制
    └── 置顶 / 独立窗口
```

## 交互与视觉决定

- 桌面导航改为带文字解释的侧栏；窄窗口收为图标，并保留可访问名称和悬停标题。
- 页面标题使用收紧字距和紧凑行高，正文保持系统字体与舒适行高。
- 侧栏、工具条和弹出菜单使用单层半透明材料；内容卡片保持实色，避免玻璃叠玻璃。
- 所有按钮在按下瞬间产生缩放反馈；页面进入只做短距离、无弹跳的 materialize。
- Android 同步展开使用无回弹 spring，可在反向点击时重新定向。
- 没有新增手势驱动抽屉或拖拽面板，因此没有为装饰动效引入运动库。
- 完整支持 `prefers-reduced-motion`、`prefers-reduced-transparency`、`prefers-contrast` 和深色模式。
- 用户可见文案集中到字符串文件；未实现的按钮和虚假同步状态被删除。

## 明确拒绝的方案

- 不把半透明材料铺满所有内容卡片。
- 不为桌面常规页签引入底部 Sheet、橡皮筋拖拽或惯性投掷。
- 不让桌面、iOS、Android 共用 UI 组件或动画实现。
- 不用动画掩盖等待，不增加人为延迟。
- 不重新增加“未来可能有用”但当前无行为的设置、编辑或新建入口。

## 验证

- Desktop：32 项测试通过，TypeScript 类型检查通过，真实 Electron 四个工作区与 JSON 工具菜单复验通过。
- iOS：iPhone 17 Pro 模拟器 build 成功；安装后验证首页同步收起/展开和原阅读恢复路径。
- Android：debug build 与单元测试通过；安装后验证同步收起和文件“更多”菜单。
- 业务契约、转换引擎、同步数据结构和隐私边界未改变。

# AI 竞品功能取舍与落地策略

更新时间：2026-07-03

## 一、结论

墨览不做成 Obsidian，也不做成 Notion。

墨览应该吸收它们的好用机制，但保持更窄的定位：

**手机上的 Markdown / JSON 文件收件箱 + 阅读编辑 + AI 可读化工具。**

核心目标仍然是：用户从微信、QQ、文件管理器、GitHub、电脑传输中拿到散落文件后，能够马上阅读、复制、转换、分享，并把有价值内容整理成 AI 能读取的材料。

## 二、Obsidian 给我们的启发

Obsidian 的优势不在“打开一个文件”，而在长期知识库：

- 本地 Markdown 文件属于用户自己。
- 文件夹 / Vault 让用户有长期存放感。
- 双链、反向链接、图谱、插件、主题支撑重度知识管理。
- 移动端也服务于同一套本地知识库。

墨览应该借鉴：

- 本地优先，文件不被平台吞掉。
- 最近文档、收件箱、归档让用户知道文件在哪里。
- Markdown 保持原始文本可读、可导出、可迁移。

墨览不应该照搬：

- 不做图谱。
- 不做插件市场。
- 不做复杂双链知识库。
- 不把手机端变成重型写作工具。

原因：我们的高频场景是“别人发来一个文件，我要马上看、复制、转发”，不是“长期搭建个人知识网络”。

## 三、Notion AI 给我们的启发

Notion AI 的关键不是普通聊天，而是“在文档上下文里执行动作”：

- 对当前页面总结。
- 改写、翻译、提取行动项。
- 选中文本后 Ask AI。
- 基于工作区和连接应用做问答。
- 历史对话和上下文连续使用。

墨览应该借鉴：

- AI 入口在阅读之后出现，不抢阅读第一优先级。
- AI 操作围绕当前文件和选中片段，而不是空白聊天框。
- 常用动作做成按钮：摘要、提取提示词、提取待办、解释 JSON、转成 AI 可读 Markdown。
- AI 输出必须能一键复制或导出。

墨览不应该照搬：

- 不做 Notion 数据库。
- 不做项目管理。
- 不做多人协作工作区。
- 不做跨 Slack / Google Drive 的企业搜索。

原因：Notion 的优势是平台级 workspace，墨览的优势应是轻、快、离线优先、文件入口清楚。

## 四、国内工具给我们的边界提醒

WPS AI、Kimi Docs、夸克等国内产品已经很强：

- WPS AI 强在 Office 内写作、总结、改写、翻译和协作。
- Kimi Docs 强在 Word / PDF / PPT / Excel 的生成、转换、审阅和报告化。
- 夸克强在系统级 AI 搜索、文档总结、格式转换、网盘和多端入口。

墨览不能硬拼大而全。

墨览应该避开：

- 完整 Office 编辑。
- PPT 生成。
- 复杂 PDF 批注。
- 大规模云盘。
- 通用 AI 聊天。

墨览应该强化：

- 微信 / QQ 文件打开入口。
- Markdown / JSON 手机阅读体验。
- 提示词一键复制。
- JSON 智能阅读和字段复制。
- Office / PDF 转成 AI 可读 Markdown 的轻量链路。
- 散落文件收件箱与价值筛选。

## 五、建议新增的 AI 功能

### 1. AI 阅读卡片

打开文件后仍然先阅读。AI 只作为阅读后的辅助入口。

卡片内容：

- 这是什么文件。
- 三句话摘要。
- 关键段落。
- 可复制提示词。
- 待办 / 结论。
- 是否值得保存。

V1 可先做本地规则识别骨架，V2 接入真实大模型。

### 2. 有用文件筛选

AI 帮用户判断这个文件是否值得保留：

- 值得保留：PRD、提示词、规则、代码文档、配置说明。
- 临时看看：普通聊天导出、零散文本。
- 低价值：空文件、乱码、重复、无结构内容。

注意：筛选不能挡住阅读。阅读永远是第一动作。

### 3. 提示词自动提取

从 Markdown / JSON 中识别：

- prompt
- system message
- rules
- todo 指令
- 常用命令
- JSON 里的 prompt / instruction / content 字段

识别后变成“一点即复制”的片段列表。

### 4. JSON 智能阅读

JSON 不只展示树，还要支持：

- 自动格式化。
- key 含义解释。
- 折叠大数组。
- 提取 prompt / config / api 字段。
- token / secret / key 敏感字段提醒。
- 一键复制字段值或路径。

### 5. AI 可读转换

格式转换目标不是单纯“能转”，而是输出 AI 更容易读取的 Markdown：

- 标题层级正确。
- 表格尽量保留。
- 代码块保留。
- 图片 / 扫描件后续做 OCR。
- 转换后给出 AI 可读评分。

### 6. 文件收件箱

从微信、QQ、文件管理器打开过的文件进入收件箱。

状态：

- 未处理
- 已阅读
- 已复制
- 已分享
- 已转换
- 已归档

这为后续云备份、历史记录、筛选有用资源打基础。

## 六、近期实现顺序

### P0

- 修复 Android / iOS 安全区，顶部工具栏不能压状态栏。
- 阅读页底部操作栏提高不透明度，避免正文透出。
- 最近 / 提示词 / 转换弹层降低遮罩压迫感。
- 新增“AI”入口和“AI 阅读卡片”本地骨架。

### P1

- 提示词自动提取。
- JSON 敏感字段提醒。
- 文件价值判断标签。
- 收件箱状态。

### P2

- 接入真实 AI 服务。
- 云备份与跨端同步。
- 批量文档 AI 可读评分。

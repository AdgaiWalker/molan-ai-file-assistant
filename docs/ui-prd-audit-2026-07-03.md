# UI / PRD 一致性评审：苹果团队口径

> 日期：2026-07-03
> 证据：用户提供的手机 App UI 图、桌面快贴窗 UI 图、`PRD.md`

## 总评

当前方向成立。

这套 UI 已经抓住了墨览的核心：手机端快速打开 Markdown / JSON，阅读优先，提示词快贴独立成能力，转换服务分享，云端服务 AI 读取。整体比之前更轻、更清楚，也更接近 iOS 原生工具感。

但它还不是完整 PRD 方案。现在的图更像“主功能展示稿”，缺少若干关键流程状态：从微信 / QQ 打开、编辑保存、分享结果、离线状态、权限引导、错误处理、首次登录 / 不登录分支。

## 已覆盖得比较好的部分

| PRD 能力 | 当前 UI 状态 | 评价 |
|---|---|---|
| 首页快速回到文件和提示词 | 已有最近文件、快捷入口、同步状态 | 成立，首页克制，不像营销页 |
| Markdown 阅读 | 已有阅读页、底部操作、AI / 转换 / 分享入口 | 成立，阅读优先感明确 |
| JSON 阅读 | 已有树形、搜索、复制 key/value/JSONPath | 方向正确，符合“一等格式” |
| 提示词库 | 已有搜索、最近复制、收藏、分类、一键复制 | 很关键，已成为产品差异点 |
| App 内快贴 | 已有底部弹窗场景 | 成立，能服务 AI App 内复制粘贴 |
| 转换中心 | 已有“给 AI 读 / 给别人看 / 给别人改”分段 | 很好，和 PRD 的转换配方一致 |
| AI 读懂前置卡片 | 已有 AI 读懂底部卡片、保存云端 | 方向正确，但文案要改成“AI 可读取” |
| 云端收件箱 | 已有文件状态、来源、电脑快贴在线 | 成立，能表达多端互通 |
| 桌面置顶快贴窗 | 已有主面板、Mini、命令、详情、拖拽转换 | 成立，符合开发者旁边固定小窗场景 |

## 主要缺口

### 1. “从微信 / QQ 打开”的 P0 入口没有被画出来

PRD 里最关键的第一幕是：微信 / QQ 收到 `.md` / `.json`，点“其他应用”，最多滑动一两下找到墨览。

当前 UI 直接从首页和阅读页开始，缺少：

- 微信 / QQ 文件卡片 → 其他应用 → 墨览的入口流程
- 首次被系统询问打开方式时的状态
- 找不到墨览时的引导
- Android 不同系统分享面板差异

裁定：必须补一组“外部打开流程图”，这是市场竞争点。

### 2. 编辑闭环还没有画完整

PRD 要求 Markdown / JSON 都能读、能改、能复制、能分享。

当前图有阅读和 JSON 复制，但缺少：

- Markdown 编辑页
- JSON 原文编辑页
- JSON 格式化 / 校验错误
- 草稿自动保存
- 保存副本
- 编辑后直接分享

裁定：编辑不是最高频，但属于核心承诺，必须补。

### 3. 分享结果缺少最终落点

PRD 里转换不是为了“生成文件”本身，而是为了发给微信 / QQ / 其他人。

当前转换页还停在队列和结果，缺少：

- 转换成功后的分享动作
- 分享到微信 / QQ / 系统面板
- 分享原文件、纯文本、PDF、Word 的选择
- 最近分享方式
- 分享失败 / 权限失败

裁定：转换页底部应优先出现“分享结果”，保存是次级。

### 4. 离线优先没有可见表达

PRD 明确要求本地优先、离线优先、默认不上传。

当前多处出现“已同步”“保存到云端”，但缺少用户放心的边界：

- 当前文件只在本机
- 未登录也可阅读 / 编辑 / 复制 / 转换
- 保存到云端前确认
- 敏感字段提醒
- 离线可用状态

裁定：云端入口要克制，不能让产品看起来像网盘。

### 5. AI 表述需要更准确

用户已经明确：目标是“让 AI 能读”，不是吹成“AI 读懂”。

当前图里有“AI 读懂”，建议统一改为：

- AI 可读
- 转给 AI 读
- 保存为 AI 可读资源
- AI 可读取评分

裁定：少用“智能理解”，多用“可读取、可复用、可生产”。

### 6. 提示词快贴缺少变量模板和组合复制

PRD 里提示词不是简单收藏夹，还要支持变量模板、片段组合、从 Markdown / JSON 导入。

当前 UI 有一键复制和详情，但缺少：

- `{{文件内容}}`、`{{代码片段}}`、`{{JSON}}` 变量
- 组合多个提示词
- 从当前文件片段保存为提示词
- 复制整个分组

裁定：提示词库要从“列表”升级为“快贴工作台”。

### 7. 桌面端快贴窗方向对，但还缺少 AI / CLI 连接

桌面图已经非常接近用户场景：固定在开发工具旁边，小窗口、置顶、快速复制。

还缺：

- 登录 / 设备同步状态的异常页
- 与手机提示词库同步冲突
- CLI / MCP 可读入口提示
- 快捷键设置
- 复制后自动回到上一个窗口的行为说明

裁定：桌面快贴窗可以作为 P1 亮点，但不要替代 CLI 转换主线。

## 需要补的 UI 图

1. 微信 / QQ 打开 `.md` / `.json` 的系统流程。
2. 首次使用和打开方式引导。
3. Markdown 编辑页。
4. JSON 编辑页：格式化成功、校验失败。
5. 转换成功后的分享页。
6. 分享到微信 / QQ / 系统面板后的状态。
7. 离线状态、未登录状态、保存到云端确认。
8. 提示词变量模板、组合复制、从文件导入。
9. Android 悬浮快贴权限与小窗。
10. iOS 键盘扩展 / 分享扩展概念图。
11. 云端同步冲突和历史版本。
12. 桌面端登录、同步异常、快捷键设置、CLI / MCP 连接说明。

## 苹果团队设计裁定

- 保留当前视觉方向：白底、轻边框、原生导航、少色彩、蓝色只给主动作。
- 首页再减一点：近期文件和快捷入口足够，不要塞更多运营内容。
- 阅读页是全产品的核心，不要让 AI 卡片抢阅读主位。
- 底部操作可以保留，但“复制”应始终是最容易触达的按钮。
- 云端入口要温和：默认本地，用户主动保存，别做成网盘。
- 桌面快贴窗是好点子，尤其适合开发者，但第一优先级仍是手机端打开和阅读。

## 结论

当前 UI 可以作为主视觉方向继续推进，但还不能算 PRD 全覆盖。

下一步建议先补“外部打开流程 + 编辑闭环 + 分享闭环 + 离线/云端边界”四组图，再进入开发对齐。
